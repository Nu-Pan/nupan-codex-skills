# Python 固有の品質検証を支えるスキルの仕様

## 目的と適用場面

プロジェクトに合う Python 環境と検証手段を選び、変更やレビューの判断に必要な根拠を得る。Python コードの変更・レビューに伴う検証と、Python の開発環境、配布、品質ゲート、性能計測の整備に適用する。

責務は、Python 固有の環境と検証方法を選んで実行することである。実装の責務分割やテストケースの設計は、利用者の要求と対象プロジェクトの契約から判断する。レビューや検査だけの依頼では依存や設定を変更せず、Python を利用した道具を実行するだけの作業には適用しない。

## プロジェクトの環境を使う

設定ファイルと開発手順から、Python のバージョン、依存管理方法、パッケージ構成、品質ゲートを確認し、宣言された環境を使う。バージョン指定がなければ Python 3.11 以上、依存管理方法がなければリポジトリ内の `.venv` を使う。検査は選択したインタープリターから起動し、開発依存をグローバル環境へ追加しない。

既存の検査で何を確かめられるかを調べ、不足する検証に合うツールを選ぶ。例えば、静的検査には Ruff や mypy が候補になる。導入が必要な場合は、その検証目的を説明し、プロジェクトの開発依存へ記録する。未導入のツール一式を追加することを完了条件にしない。

## Python の挙動と配布を検証する

プロジェクトのテストランナーと構成を使う。pytest では、テストが操作するファイルシステム、環境変数、作業ディレクトリなどを fixture で隔離する。利用が任意とされている外部実行ファイルがない場合は、理由を明示してテストをスキップできる。

パッケージとして公開するファイルの構成やリソースを変更した場合は、インストール後を想定した配置でも、モジュールをインポートでき、リソースを参照できることを確認する。チェックアウトしたソースの配置だけで成功を判断しない。

処理が停止して完了しないおそれのあるテストには、実行を打ち切れる仕組みを用意する。既存の方法で不足する場合は、例えば pytest-timeout を候補とし、正常時の実測と環境によるばらつきから上限を選ぶ。停止検出用のタイムアウトは、性能要件を満たすかどうかの判定とは区別する。

## 静的検査とリソース検査を選ぶ

lint、フォーマット、型の検査は既存の設定に従い、検証時はファイルを書き換えないモードを使う。型エラーや警告を広い除外や根拠のない型指定で隠さない。新しい検査は、既存コードに合う範囲と厳しさから導入する。

リソースの寿命を検証するときは、Python の開発モードを有効にし、`ResourceWarning` をエラーとして扱う方法を使える。既存の品質ゲートが定めていれば、その設定で実行する。評価は、その検査で観測できるリソースの扱いに限る。

警告の除外が必要なら発生元を調べ、第三者に由来すると確認できた警告だけを、理由と範囲を明示して除外する。

## 判断に合う計測手段を選ぶ

性能の判断が必要かを、依頼や性能要件、処理量や待ち時間への影響、性能回帰の兆候から確かめる。必要な場合は代表的な経路を実測する。既存のベンチマークを優先し、既存実装では変更前後を同じ条件で比較する。新規実装では、正しく動く版の所要時間を記録する。

Python で観測する内容に応じた手段の例を示す。

| 観測したいこと | 手段の例 |
| --- | --- |
| 代表経路の経過時間 | 既存のベンチマーク、`time.perf_counter_ns()` |
| 独立した小さな処理の時間 | `timeit` |
| 実行を分離した反復計測や継続比較 | `pyperf`、`pytest-benchmark` |
| CPU 時間の内訳 | `cProfile` と `pstats`、`py-spy` |
| メモリの割り当てや使用量 | `tracemalloc`、Memray |

マイクロベンチマークが示すのは切り出した処理の時間なので、利用者の待ち時間を判断するには起動や I/O を含む経路を測る。原因を調べた後は、計測への影響を除くためプロファイラーなしで再計測する。計測は許可された権限で行い、継続的な合否判定にはプロジェクトの性能要件と安定して比較できる条件を使う。

## 検証結果を判断へつなげる

変更中は関連箇所を検査し、完了前にはプロジェクトが定める品質ゲートとテスト一式を、現在の成果物に対して実行する。共通の品質ゲートがなければ、変更した挙動と利用側への影響を確認できる範囲を選ぶ。

ほかの規則と同じ対象・条件の検査や計測は共用する。実行した検査と結果、検証できなかった範囲を報告し、性能を判断した場合は実測値と条件、ツールを追加した場合は必要性を添える。
