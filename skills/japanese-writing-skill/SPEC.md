# 日本語の技術文書を書くスキルの仕様

## 目的と適用場面

読み手が対象の意味や役割を理解し、必要な判断をできる日本語の技術文書を作る。実装や調査に付随する文書も含め、技術文書の作成・改訂に適用する。配布設定では暗黙の適用を有効にする。

## 伝える内容を選ぶ

文章全体と各節で、何を伝えたいかを先に示す。対象は共通する性質や役割から説明し、適切な技術用語があれば使う。読み手が個々の項目を突き合わせて原則を推測しなくても、扱いを判断できる説明にする。

情報を加える前に、それがないと読み手のどの重要な判断が変わるかを考える。条件や例外は、文脈上自然に起こる好ましくない判断を防ぐために書く。個々の要素を確定する必要がある列挙は残し、例は考え方を理解するために選ぶ。

中心的な意図を明確にしたうえで、読み手が文脈に沿って具体化することを信頼する。目的を満たす複数の判断が成り立つ余地を残し、そのたびに任意・未定義の断り書きを付けない。

## 説明のまとまりを組み直す

利用者の依頼と文書の目的を確認し、要求と参考情報を区別する。関連する説明をファイル境界にかかわらず一緒に読み、意図を直接伝える構成へ組み直す。説明を足す前に削除や統合を試し、例外が重なるときは主文や概念の切り方を見直す。変更履歴を知らない読み手にも自然に伝わることを、差分の小ささより重視する。

推敲では要件と事実関係を保ち、仕様改訂では利用者の依頼に基づく意味の変更を反映する。短くするためだけに保証を弱めたり、根拠のない事実を補ったりしない。引用やコードなど正確な表記が意味を持つ情報と、利用者が維持を指定した表記を保つ。対象領域の正しさと変更権限は、依頼とその領域の根拠に従う。

## 読みやすい形を選ぶ

指定がなければ GFM で書き、一文の主な内容を明確にする。論理的につながる説明は自然な段落にまとめ、情報の関係に合う見出しやリストを使う。項目数によって形式を決める前に、列挙自体が必要かを考える。

判断の違いが分かる少数の対比例を、実行時の指示にも含める。

| 文脈 | 記述の選び方 |
| --- | --- |
| 執筆条件を守ることを伝える | 「目的、想定読者、文体、出力形式の指定に従う」は、「指定された執筆条件に従う」で足りる。 |
| 対応環境を保証する | 「対応OSは Ubuntu 24.04、macOS 15、Windows 11 とする」は、個々の環境を残す。 |
| 現在の問題を報告する | 「確認時点で未解決の問題を載せる」に、解決済みの問題の除外を重ねる必要はない。再検証を義務付けるなら、別の要求変更となる。 |

失敗時に必要な行動が変わる条件も保つ。たとえば「更新に失敗したら元のファイルを保つ。復元にも失敗した場合は、復元用コピーの場所を報告する」は、その違いを伝えている。

## 出力と評価

完成した文章を、求められた形式で提示する。ファイルを更新した場合は作業結果を報告し、求められていない文書全文や編集経緯を応答へ重複して載せない。

中心的な意図から必要な判断ができるか、要件と事実が保たれているかを評価する。残る解釈の余地は目的に照らして判断し、文の長さや特定の接続詞の有無で合否を決めない。
