# write-repository-routing-docs の仕様

## 目的

このスキルは、ソフトウェアリポジトリで読むべきファイルやディレクトリを選ぶためのルーティング文書を作成または変更する。
読者が対象本文を読む前に、その対象へ進むべきか判断できる情報を提供する。

作成または変更後のルーティング文書は、次の状態を満たす。

- 対象本文の代替ではなく、読む先を選ぶ案内になっている。
- 対象の責務と、対象を読むべき条件が分かる。
- 対象を読まなくてよい条件と、より直接的な読む先が分かる。
- 対象の現在内容だけを根拠としている。
- ファイル名、hash、schema など、機械的に補える情報を意味説明へ混ぜていない。
- 広すぎる関連条件や、推測した将来用途を含んでいない。

このファイルは、`write-repository-routing-docs` のスキル仕様の正本である。
実行時仕様を変更するときは、先にこのファイルを変更する。

## 適用条件

次のようなリポジトリ内ルーティング文書を作成または変更する場合に、このスキルを使用する。

- `INDEX.md` と同等のファイル案内
- ディレクトリ内のファイルへ進むための索引
- 上位索引から下位索引へ進むためのエントリー
- AI agent または人間が、必要な本文だけを選ぶための案内
- `Summary`、`Read this when`、`Do not read this when` を持つエントリー

対象リポジトリに既存のファイル名や形式がある場合は、その規約を使用する。

## 対象外

次の文書は、このスキルの対象にしない。

- 本文の内容を網羅的に説明する README
- 章番号や見出しだけを並べる通常の目次
- API reference や設計仕様の本文
- ファイル一覧を機械的に列挙するだけの文書
- 対象本文を読まずに作る推測上の案内

ルーティング文書の作成依頼がない通常の実装作業では、新しい索引を自動的に追加しない。

## 用語

### ルーティング文書

ルーティング文書は、同じ階層または下位階層の対象から、作業に必要な本文を選ぶための案内である。
本文の正本や代替説明としては扱わない。

### エントリー

エントリーは、1 つのファイルまたはディレクトリについて、要約、読む条件、読まない条件を示す単位である。

## 入力と前提

必要な入力を次に示す。

- エントリーの対象となるファイルまたはディレクトリ
- 対象のオリジナル本文
- 必要に応じて参照する同階層または関連対象の本文
- 対象リポジトリに既存のルーティング文書規約がある場合は、その規約
- 既存文書へ統合する場合は、その文書の構造

エントリーの意味情報は、対象のオリジナル本文を第一の根拠とする。
既存のルーティング文書と対象本文が食い違う場合は、対象本文を根拠として扱う。

ファイルを対象とする場合は、そのファイル本文をオリジナル本文とする。
ディレクトリを対象とする場合は、そのディレクトリ直下のルーティング文書をオリジナル本文とする。
ディレクトリ直下にルーティング文書がない場合は、任意の子孫を再帰的に要約してエントリーを作らない。
依頼範囲に含まれる場合は直下のルーティング文書を先に作成し、含まれない場合は根拠不足として扱う。

既存規約がなく、利用者が新しいルーティング文書の作成を明示した場合は、`INDEX.md` を既定のファイル名とする。
各エントリーには、`Summary`、`Read this when`、`Do not read this when` を使用する。

## 実行時の規則

### 本文を読む前の判断材料を書く

- 対象を読むべき作業、質問、変更の条件を判断できる意味情報を書く。
- 対象が担う責務を書く。
- 同階層の別対象ではなく、その対象へ進む理由を書く。
- 対象本文を読まなければ理解できない詳細を、エントリーへ展開しない。
- 関連しそうという理由だけで対象へ進ませる広すぎる条件を書かない。

### Summary を書く

- 対象の現在の責務を簡潔に要約する。
- 対象が扱う内容と、下位要素への入口としての位置付けを書く。
- 本文の処理手順、全識別子、全仕様を列挙しない。
- 対象名を言い換えるだけの要約にしない。

### Read this when を書く

- 対象を読むべき具体的な作業、質問、変更条件を書く。
- 対象から確認を始めるとよい条件を書く。
- 対象の責務と直接結び付く条件だけを書く。
- 「関連する作業」のように、境界を判断できない条件を書かない。

### Do not read this when を書く

- 対象を読まなくてよい条件を書く。
- 別のファイルまたは下位項目へ直接進む方が適切な条件を書く。
- より直接的な読む先が分かる場合は、その役割を示す。
- 対象外の境界を、対象本文から根拠を持てる範囲で示す。

### 対象内容だけに基づく

- 対象本文から根拠を持って言える責務、入口、読む条件だけを書く。
- 対象外の責務や将来の用途を推測で追加しない。
- 対象本文に存在しない実装や仕様を、エントリー上で断定しない。
- 対象本文と既存エントリーが乖離している場合は、本文へ合わせてエントリーを更新する。
- ディレクトリエントリーは、そのディレクトリ直下のルーティング文書だけを対象本文として生成する。
- 直下のルーティング文書がないディレクトリを、任意の子孫ファイルから推測して要約しない。

### 機械的な情報を意味説明へ混ぜない

- ファイル名、ディレクトリ名、hash 値など、文書構造や生成処理から分かる識別情報を説明文へ繰り返さない。
- 出力 schema から分かる field 名、型、形式を自然言語で説明しない。
- 生成時刻、行数、サイズなど、ルーティング判断に不要な機械情報を書かない。
- 読むべきか判断するための意味情報だけを書く。

### ルーティング文書を使う

- 作業対象の領域を推定し、その領域に最も近いルーティング文書から読む。
- 下位ディレクトリへ進む場合は、必要に応じてその階層のルーティング文書も読む。
- ルーティング文書だけで判断できない場合は、候補となる本文を読んで確認する。
- 総当たりで本文を読む前に、ルーティング文書で候補を絞る。
- `Read this when` に作業が当てはまる対象を優先する。
- `Do not read this when` に作業が当てはまる場合は、より直接的な対象を探す。
- ルーティング文書と本文が乖離している場合は、本文を根拠にする。

## 作業手順

1. 対象リポジトリのルーティング文書規約を確認する。
2. ファイルではその本文を読み、ディレクトリでは直下のルーティング文書を読む。
3. 必要に応じて、責務境界を判断するための関連本文を読む。
4. 既存エントリーを根拠にせず、対象本文から Summary、Read this when、Do not read this when の内容を決める。
5. 既存文書へ統合する場合は、この時点で既存文書を読み、形式と配置を合わせる。
6. 既存エントリーとの重複と矛盾を整理する。
7. 対象本文だけで各文の根拠を説明できるか確認する。

## 出力

利用者または対象リポジトリが別の形式を指定していない場合は、各対象を次の構造で記載する。

```markdown
# `{{target-name}}`

## Summary

- {{target-summary}}

## Read this when

- {{condition-for-reading}}

## Do not read this when

- {{condition-for-not-reading}}
```

各節には、少なくとも 1 つの意味情報を記載する。
既存文書を変更した場合は、利用者が求めていない限り、文書全体を最終回答へ重複して掲載しない。

## 検証

完了前に、次の条件を確認する。

- 対象本文を読む前に、対象へ進むべきか判断できる。
- Summary が、対象の責務と入口としての位置付けを示している。
- Read this when が、直接関係する具体的な条件を示している。
- Do not read this when が、対象外とより直接的な読む先を示している。
- 対象本文の詳細を、エントリーへ過剰に展開していない。
- 対象本文から根拠を持てない責務や将来用途を含んでいない。
- ディレクトリエントリーが、直下のルーティング文書を根拠としている。
- 広すぎて判断に使えない条件を含んでいない。
- 機械的に補える識別情報や形式情報を意味説明へ混ぜていない。
- ルーティング文書と対象本文が整合している。

1 つでも満たさない場合は、完了としない。

## 重視する価値

ルーティング文書の価値は、本文を読む前に読む先を絞れることにある。
本文を要約し尽くすことより、不要な文脈を読まずに済む明確な境界を重視する。

- `oracle/src/oracle/prompt_builder/parts/index_entry_standard.py`
- `oracle/src/oracle/prompt_builder/parts/routing_rule.py`
- `oracle/src/oracle/acp_builder/indexing/index_entry.py`
- `oracle/src/oracle/acp_builder/indexing/index_entry.json`
