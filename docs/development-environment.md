# スキル開発環境の規約

## 目的

この文書は、リポジトリでスキルを開発するための共通環境とテスト実行方法を定義する。
すべてのスキルを同じ入口から検証できる状態を維持する。

スキルの構造と保守方法には、[`skill-repository-spec.md`](skill-repository-spec.md) を適用する。
この文書は、その共通仕様にある開発環境と自動テストの規則を具体化する。

## 基準環境

開発には、リポジトリを取得して Python の分離環境を作成できる環境を使用する。
基準となるツールを次に示す。

- Git
- Python 3.12
- Python の `venv` と `pip`
- pytest

Python 3.12 を基準バージョンとする。
別の Python バージョンも使用できる。
完了前に、基準バージョンで検証できる状態を維持する。

コマンドは、リポジトリのルートから実行する。
検証処理は、開発者固有の実行環境を前提にしてはならない。
禁止する前提を次に示す。

- 特定の絶対パス
- 手動で設定した `PYTHONPATH`
- `requirements-dev.txt` に記録されていないパッケージ

## 環境の構築

プロジェクトローカルの `.venv` に開発環境を作成する。
システムの Python 環境へ開発用パッケージを直接インストールしない。

POSIX 互換シェルでは、次のコマンドをリポジトリのルートで実行する。

```bash
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements-dev.txt
```

別のシェルでは、そのシェルに対応する方法で `.venv` を有効化する。
有効化後は、使用中の Python と pytest を確認する。

```bash
python3 --version
python3 -m pytest --version
```

Python の共通開発依存は、ルートの `requirements-dev.txt` に記録する。
テストに新しいパッケージが必要な場合は、一時的な手動インストールだけで済ませてはならない。
再現に必要な依存条件を `requirements-dev.txt` へ追加する。

ローカル環境や検証時の生成物はコミットしない。
追跡対象から除外する生成物を次に示す。

- `.venv/`
- `__pycache__/`
- `.pytest_cache/`
- カバレッジ出力

## テストの配置

スキル固有の自動テストは、`skills/{{skill-name}}/tests/` に配置する。
このディレクトリは保守用であり、`dist/` には含めない。

機械的に結果を判定できる振る舞いには、スキル固有のテストを追加する。
代表的な対象を次に示す。

- `dist/scripts/` にある実行時スクリプト
- 構造化データを扱う決定的な処理
- 過去に不具合が発生した決定的な振る舞い

文章による指示だけで構成され、結果を安定して自動判定できないスキルでは、`tests/` を省略できる。
その場合も、リポジトリ検査と現実的な依頼による動作検証を省略してはならない。

ルートの `tests/` には、リポジトリツールを検証するテストを配置する。
スキル固有の振る舞いを、ルートの `tests/` へ混在させない。

pytest の共通収集設定は、ルートの `pytest.ini` に記録する。
スキルごとの pytest 設定ファイルは追加しない。
配布物の `dist/` は、共通収集の対象から除外する。

## テストの記述

共通テストランナーには pytest を使用する。
新規作成または変更するスキル固有のテストは、pytest が直接収集できる形式で記載する。
スキル固有のテストコードに適用する規則を次に示す。

- テストモジュール名を `test_*.py` とする。
- テスト関数名を `test_*` とする。
- 外部から観測できる振る舞いと重要な失敗条件を検証する。
- ファイルシステムを使用する場合は、pytest の `tmp_path` などでテストごとに分離する。
- テストの実行順序へ依存しない。
- 外部ネットワークへ依存しない。
- 秘密情報へ依存しない。
- 開発者の端末状態へ依存しない。

複数のテストで共有する fixture が必要な場合だけ、最も狭い共有範囲に `conftest.py` を配置する。
テスト専用の補助処理を、配布物へ追加してはならない。

## pytest の実行

pytest は、有効化した開発環境から `python3 -m pytest` の形式で実行する。
この形式により、テスト対象と依存パッケージを同じ Python 環境へ結び付ける。

変更した一つのスキルだけを検証する場合は、そのスキルのテストディレクトリを指定する。

```bash
python3 -m pytest skills/{{skill-name}}/tests
```

複数のスキルを変更した場合は、変更したスキルのテストディレクトリを一回の実行へ列挙する。

```bash
python3 -m pytest \
  skills/{{first-skill-name}}/tests \
  skills/{{second-skill-name}}/tests
```

リポジトリツールだけを検証する場合は、ルートのテストディレクトリを指定する。

```bash
python3 -m pytest tests
```

リポジトリ全体を検証する場合は、ルートテストと全スキルを明示的に探索対象とする。

```bash
python3 -m pytest tests skills
```

対象スキルに `tests/` がない場合は、存在しないパスを指定して pytest を実行しない。
空の `tests/` を作成して、テストを実行したことにしてはならない。

## 完了条件

変更したスキルにテストがある場合は、対象スキルの pytest とリポジトリ検査の両方を成功させる。

```bash
python3 -m pytest skills/{{skill-name}}/tests
python3 scripts/validate_skills.py {{skill-name}}
```

リポジトリ全体へ影響する変更では、全スキルと全テストを成功させる。
全体検証が必要な変更を次に示す。

- 共通仕様または開発環境規約の変更
- 雛形生成または検査処理の変更
- 開発依存の変更

```bash
python3 scripts/validate_skills.py
python3 -m pytest tests skills
```

pytest がテストを収集できない状態は、成功とみなさない。
完了条件の回避に使用してはならない変更を次に示す。

- 失敗したテストの削除
- 理由のない skip
- 検証範囲の縮小

失敗原因を修正してから、同じコマンドを再実行する。
