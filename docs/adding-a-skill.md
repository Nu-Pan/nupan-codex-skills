# 新しいスキルを追加する

## 概要

新しいスキルは、共通の雛形から作成する。
仕様を先に確定し、配布物へ反映してから検証する。

共通規則の正本は、[`skill-repository-spec.md`](skill-repository-spec.md) である。

## 1. スキルを定義する

生成前に、スキルの目的と利用例を確定する。
最低限、次の内容を明らかにする。

- スキルが実現する結果
- スキルを使用する依頼や状況
- スキルの対象外とする依頼
- 再利用するスクリプト、参照情報、素材の必要性

利用例から、短く動作を表すスキル名を決める。
スキル名には、小文字の英字、数字、ハイフンだけを使用する。

## 2. 雛形を生成する

リポジトリのルートで生成コマンドを実行する。

```bash
python3 scripts/create_skill.py <skill-name>
```

生成コマンドは、既存のディレクトリを上書きしない。
生成後に表示されるファイルを順番に編集する。

## 3. 仕様を記載する

最初に `skills/<skill-name>/SPEC.md` を編集する。
雛形の `{{TODO: ...}}` をすべて具体的な仕様へ置き換える。

仕様には、目的、適用条件、実行時の規則、出力、検証条件を記載する。
重要な規則には、必要に応じて根拠や前提も記載する。

## 4. 配布物を実装する

`SPEC.md` の内容を、配布用の `SKILL.md` と `agents/openai.yaml` へ反映する。

`SKILL.md` では、次の点を確認する。

- frontmatter の `name` がスキル名と一致している。
- `description` に機能と適用条件が記載されている。
- 本文に、実行時に従う規則だけが命令形で記載されている。
- `{{TODO: ...}}` が残っていない。

`agents/openai.yaml` では、次の点を確認する。

- 表示名と短い説明がスキルの内容を表している。
- `default_prompt` に `$<skill-name>` が含まれている。
- 暗黙の呼び出しなど、必要な設定だけが追加されている。

実行時リソースが必要な場合だけ、配布物へ対応するディレクトリを追加する。
追加できるリソースの種類を次に示す。

- `scripts/`
- `references/`
- `assets/`

## 5. 利用方法を記載する

`skills/<skill-name>/README.md` に、概要、仕様と配布物へのリンク、固有の使用方法、具体的な呼び出し例を記載する。
共通のインストール方法やリポジトリの保守方法は記載しない。
ルート `README.md` の収録スキル一覧にも、リンクと概要を追加する。

共通の利用方法を案内する必要がある場合は、ルート `README.md` へリンクする。

スキル固有の保守規則がある場合だけ、スキルの直下に `AGENTS.md` を追加する。
共通仕様を `AGENTS.md` へ複製しない。

## 6. 検証する

対象スキルを指定して、構造とメタデータを検証する。

```bash
python3 scripts/validate_skills.py <skill-name>
```

雛形の未確定項目や、ルート README への追加漏れも検出される。
検査結果を修正し、成功するまで再実行する。

複雑なスキルでは、実際の利用者が行う形式の依頼で動作も検証する。
