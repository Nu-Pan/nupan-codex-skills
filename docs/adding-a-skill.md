# 新しいスキルを追加する

スキルは、利用例から仕様を定め、配布物を作って検証する。
構造と保守方法は [共通仕様](skill-repository-spec.md)、環境構築と pytest の実行は [開発環境の規約](development-environment.md) に従う。

## 利用例から目的を定める

利用者が実現したい結果と、スキルが役立つ場面を確認する。
単独でその結果を得られる方法と、既存スキルとの責務の関係を考える。
必要なスクリプトや参照情報は、この作業から選ぶ。
対象外の説明は、適用場面を誤解しやすい場合に添える。

動作を短く表すスキル名を決め、リポジトリのルートで雛形を生成する。

```bash
python3 scripts/create_skill.py {{skill-name}}
```

生成コマンドは既存のパスを上書きしない。
名前の形式と予約語は共通仕様に従う。

## 仕様から配布物を作る

最初に `skills/{{skill-name}}/SPEC.md` を編集する。
目的と判断原則から、必要な作業と期待する結果が分かる仕様にする。
雛形の構成は説明に合わせて組み直し、`todo-` で始まるプレースホルダーを解消する。
独立性と合成で固有の注意が必要なら、対応する規則へ組み込む。

確定した仕様を `dist/SKILL.md` と実行時リソースへ反映する。
実行時の判断に役立つ短い理由や対比例も含められる。
参照情報を分離する場合は、使う場面を `SKILL.md` で案内する。
別のスキルを任意に参照する場合は、そのスキルがなくても成立する方法を用意する。

表示情報と案内を配布物へ合わせる。

- `dist/agents/openai.yaml` に表示情報と具体的な依頼例を記載する。
- スキル別 `README.md` に概要と仕様・配布物へのリンクを記載する。
- ルート `README.md` の収録スキル一覧を更新する。

## 評価条件を定める

`skill-composition.json` に単独シナリオを追加し、新しいスキルと既存の全スキルとの関係を分類する。
責務が重なる組み合わせには、規則を一緒に適用できることを確かめる現実的な依頼を用意する。
同じシナリオで複数の組み合わせを検証できる場合は共用する。
任意参照は、参照箇所とフォールバックも台帳へ記載する。

決定的な処理には、スキル別の `tests/` に pytest のテストを用意する。
外部から観測できる結果と重要な失敗条件を確かめる。
文章による判断は前向き評価で確認する。

## 検証する

開発環境を有効にして、リポジトリ検査を実行する。
スキル固有のテストがある場合は、そのテストも実行する。

```bash
python3 scripts/validate_skills.py {{skill-name}}
python3 -m pytest skills/{{skill-name}}/tests
```

構造と台帳の検査後、単独・組み合わせシナリオを新しいセッションで評価する。
期待した結果だけでなく、不要な制約や作業を増やしていないことも確認する。
結果はシナリオ ID とともに最終報告へ記載する。
