# スキルリポジトリの共通仕様

## 目的

この仕様は、モノレポ内の全スキルに共通する構造と保守方法を定義する。
新しいスキルも既存スキルと同じ方法で作成、変更、配布、検証できる状態を維持する。

このファイルは、スキルリポジトリの共通仕様の正本である。
共通規則を変更するときは、先にこのファイルを変更する。

各スキルの機能と実行時の振る舞いは、そのスキルの `SPEC.md` で定義する。
共通仕様とスキル固有仕様を重複させない。

## 独立性と合成可能性

このリポジトリの任意のスキルは、単独でも、他の任意のスキルと同時に導入しても成立しなければならない。
スキルの追加、削除、導入順によって、既存スキルの目的、適用条件、出力、安全条件を変えてはならない。

### 単独で成立させる

各スキルの配布物には、そのスキルの実行時仕様を満たすために必要な規則とリソースを含める。
別のスキルの存在を、適用、実行、検証、完了の必須条件にしてはならない。
別のスキルの配布物、インストール先、読み込み状態を直接参照してはならない。

別のスキルとの任意連携は許可する。
任意連携では、参照先が存在しない場合も同じ要求を満たせるフォールバックを定義する。
任意連携によって省略できるのは重複する作業だけとし、目的、出力、検証、安全条件を省略してはならない。

### 規則を累積して適用する

複数のスキルが適用される場合は、ホストが定める指示の優先順位と対象リポジトリの正本仕様を守ったうえで、適用されるすべてのスキルの規則を累積する。
スキルの導入順、読み込み順、名前順によって、一方の規則で他方の規則を上書きしてはならない。

同じ計測、検査、調査、報告を複数のスキルが要求する場合は、一回の作業で各スキルの条件をすべて満たす。
対象領域が狭い規則は、広い規則と両立する範囲で詳細を追加できる。
一方へ従うと別の規則へ必ず違反する組み合わせを、リポジトリへ追加してはならない。

実行時に未確認の競合を発見した場合は、一方を任意に優先しない。
競合する作業を完了扱いにせず、両立しない規則と影響範囲を利用者へ示す。

### 追加と削除に対して閉じる

スキルを追加する場合は、既存の全スキルとの関係を確認する。
スキルを削除する場合は、そのスキルを指す台帳、文書、配布物の参照も同じ変更で整理する。
追加または削除後も、残る各スキルの単独シナリオと全スキル対の分類を完全な状態に保つ。

組み合わせの正本となる共通規則はこのファイルに置く。
具体的な組み合わせと評価条件は、リポジトリルートの `skill-composition.json` に記録する。

## スキル名

スキル名は、ディレクトリ名と配布メタデータを結び付ける識別子として扱う。
スキル名は、次の条件をすべて満たす。

- 小文字の英字、数字、ハイフンだけを使う。
- 先頭と末尾にハイフンを置かない。
- ハイフンを連続させない。
- 64 文字以内にする。
- `all` を使用しない。`all` は、共通インストールスクリプトで全スキルを指定する予約語とする。
- スキルの動作を短く表す名前にする。

同じスキル名を、次の場所で使用する。

- `skills/{{skill-name}}` のディレクトリ名
- `SKILL.md` の `name`
- `agents/openai.yaml` の `default_prompt` に含める `${{skill-name}}`

## プレースホルダー

プレースホルダーは、二重波括弧で名前を囲んだ `{{placeholder-name}}` の形式で記載する。
名前には、意味を表す英単語を使用する。
名前は、小文字の英字、数字、単独のハイフンだけで構成する。
先頭と末尾にハイフンを置かない。
ハイフンを連続させない。

雛形の未確定項目には、`todo-` で始まる名前を使用する。
たとえば、スキルの目的と成功条件の未確定項目には、`{{todo-skill-goal-and-success-criteria}}` を使用する。

## ディレクトリ構造

各スキルは、保守用ファイルと配布物を分離する。
標準構造を次に示す。

```text
skills/{{skill-name}}/
├── README.md
├── SPEC.md
├── AGENTS.md                     # スキル固有の保守規則がある場合だけ配置する
├── tests/                        # スキル固有の自動テストがある場合だけ配置する
│   ├── conftest.py               # 共通 fixture がある場合だけ配置する
│   └── test_*.py
└── dist/
    ├── SKILL.md
    ├── agents/
    │   └── openai.yaml
    ├── scripts/                  # 実行時に必要な場合だけ配置する
    ├── references/               # 実行時に必要な場合だけ配置する
    └── assets/                   # 実行時に必要な場合だけ配置する
```

`skills/` の直下には、スキルのディレクトリだけを置く。
`dist/` の直下には、配布物を直接配置する。
スキル名と同じ配布用ディレクトリを `dist/` の下へ追加しない。

## ファイルの責務

### `SPEC.md`

`SPEC.md` は、スキル固有仕様の正本とする。
エージェントが配布物を再構築できるだけの情報を記載する。

仕様で定義する情報には、次の内容を含める。

- スキルの目的と成功条件
- 適用条件と対象外の範囲
- 入力、前提条件、優先順位
- 単独実行時の成立条件と、他のスキルと重複する責務の扱い
- 実行時の規則と手順
- 出力と検証条件
- 重要な規則の根拠、前提、重視する価値

見出し名と構成は、スキルの性質に合わせて変更できる。
リポジトリ共通の保守手順は記載しない。

### ルート `README.md`

ルート `README.md` は、リポジトリ全体の利用方法と保守方法の入口とする。
README 間で共通する利用情報と保守情報は、このファイルだけに記載する。

ルート `README.md` には、次の情報を記載する。

- リポジトリの概要
- 収録スキルへのリンクと概要
- `scripts/install_skill.py` による `.agents/skills/{{skill-name}}` への共通インストール方法
- スキルに共通する呼び出し方法
- リポジトリの開発方法と検証方法

### スキル別 `README.md`

スキル別 `README.md` は、利用者がスキルの概要と正本の場所を把握するための文書とする。
README に記載しない情報は、次のとおりである。

- 使用方法
- インストール方法
- リポジトリの保守方法

スキル別 `README.md` には、次の情報を記載する。

- スキルの概要
- `SPEC.md` と配布物へのリンク

スキル固有の適用条件や想定される利用場面は、必要な場合だけ `SPEC.md` に記載する。
共通の利用方法は、ルート `README.md` だけに記載する。
ルート `README.md` の収録スキル一覧にも、そのスキルへのリンクと概要を追加する。

### `AGENTS.md`

スキル固有の保守規則がある場合だけ、`AGENTS.md` を配置する。
ルート規則やこの共通仕様を繰り返さない。

### `tests/`

`tests/` は、スキル固有の自動テストを配置する保守用ディレクトリとする。
実行時スクリプトや決定的に検証できる振る舞いがある場合に配置する。
テストには pytest を使用する。

スキル固有のテストは、`skills/{{skill-name}}/tests/` だけを指定して実行できる状態にする。
リポジトリツール自体のテストは、ルートの `tests/` に配置する。
どちらのテストも配布物へ含めない。

開発環境の構築方法とテストの実行規約は、[`development-environment.md`](development-environment.md) に定義する。

### `SKILL.md`

`SKILL.md` は、スキルを使用するエージェントが実行時に従う情報だけを記載する。
YAML frontmatter には、`name` と `description` だけを記載する。

frontmatter は、次の条件を満たす。

- `name` をスキル名と一致させる。
- `description` に、スキルの機能と適用条件を記載する。
- `description` を 1,024 文字以内にする。
- 値を未確定のまま残さない。

本文は命令形で書く。
規則の根拠、リポジトリの保守手順、インストール方法は記載しない。
詳細な参照情報が大きい場合は `references/` へ分離し、`SKILL.md` から読み込み条件を明示する。

独立性と合成可能性の共通規則を、本文へ繰り返さない。
スキル固有で実行時に必要な制約だけを、対象となる手順または検証の節へ記載する。
独立性と合成可能性だけを説明する専用の節は設けない。

### `skill-composition.json`

`skill-composition.json` は、単独評価、スキル対の分類、代表的な重複適用シナリオ、任意参照を記録する保守用台帳とする。
このファイルは配布物へ含めない。

ルート object には、次のキーだけを記載する。

- `version`: 形式のバージョン。現在は整数の `1` とする
- `optional_references`: スキル間の任意参照
- `standalone_scenarios`: 各スキルを単独で評価するシナリオ
- `combination_scenarios`: 複数スキルを同時に評価するシナリオ
- `pairs`: 全スキル対の関係

任意参照は、`source`、`target`、`locations`、`fallback` を持つ object とする。
`source` と `target` は異なる既存スキル名とする。
`locations` には、参照を含むファイルを source のスキルルートからの相対パスで重複なく名前順に記載する。
`fallback` には、target がない場合に source だけで同じ要求を満たす方法を記載する。

単独シナリオは、`id`、`skill`、`request`、`expected`、`forbidden` を持つ object とする。
各スキルに一つだけ記載する。
`request` には現実的な依頼を記載する。
`expected` には満たす結果を一つ以上記載する。
`forbidden` には、単独性または安全性を損なう結果を一つ以上記載する。

組み合わせシナリオは、`id`、`skills`、`request`、`expected`、`forbidden` を持つ object とする。
`skills` には、同時に評価する二つ以上の既存スキル名を重複なく名前順に記載する。
評価条件には、各スキルの規則が累積され、重複作業が統合されることを含める。

各 pair は、`skills`、`relation`、`scenario_ids` を持つ object とする。
`skills` には、異なる二つの既存スキル名を名前順に記載する。
`relation` は、責務が分離している `orthogonal` または同じ成果物、判断、検証、出力へ規則を加える `overlap` とする。
`orthogonal` の `scenario_ids` は空配列とする。
`overlap` の `scenario_ids` には、pair の両スキルを含む組み合わせシナリオを一つ以上記載する。
全スキルから作れる順序を問わない二要素の組を、一度ずつ記載する。

シナリオ ID は、小文字の英字、数字、単独のハイフンだけで構成する。
すべての配列は、意味上の順序がない場合は名前順に記載する。

### `agents/openai.yaml`

`agents/openai.yaml` は、利用者向けの表示情報と呼び出し設定を定義する。
文字列値は引用符で囲む。

`interface` には、次の項目を必ず記載する。

- `display_name`
- 25 文字以上 64 文字以内の `short_description`
- `${{skill-name}}` を含む `default_prompt`

アイコン、ブランド色、依存ツール、暗黙の呼び出し設定は、スキルに必要な場合だけ追加する。
`SKILL.md` を変更した場合は、表示情報と呼び出し設定が一致しているか確認する。

## 配布物

配布物には、スキルの実行時に必要なファイルだけを含める。
実行時リソースの用途を次に示す。

- `scripts/`: 繰り返し実行する処理または決定的な実行が必要な処理
- `references/`: 必要な場面で読み込む詳細な知識や仕様
- `assets/`: 出力へ組み込む雛形、画像、フォントなどの素材

必要なリソースディレクトリだけを作成する。
同じ情報を `SKILL.md` と `references/` に重複させない。

配布物には、次の保守用ファイルを含めない。

- `README.md`
- `SPEC.md`
- `AGENTS.md`
- `LICENSE`

## インストール

利用者は、リポジトリのルートで共通インストールスクリプトを実行する。
1 つのスキルをインストールする正規のコマンドを次に示す。

```bash
python3 scripts/install_skill.py {{skill-name}} {{target-repository}}
```

全スキルをインストールする正規のコマンドを次に示す。

```bash
python3 scripts/install_skill.py all {{target-repository}}
```

`{{target-repository}}` には、既存のディレクトリを指定する。
相対パスと絶対パスのどちらも使用できる。
Git リポジトリであることは要求しない。

スクリプトは、配布物を `{{target-repository}}/.agents/skills/{{skill-name}}/` へインストールする。
`.agents/skills` がない場合は作成する。

`all` を指定した場合は、`skills/` 直下にあるすべてのスキルディレクトリを名前順でインストールする。
導入先とすべての配布物を、導入先の変更前に検証する。
導入先にだけ存在するスキルは削除しない。

同名スキルがすでに存在する場合は、配布物全体を置き換える。
旧版だけに存在するファイルや、導入先で加えられた変更は残さない。
置き換えでは、配布物を一時ディレクトリへコピーしてから既存版と入れ替える。
入れ替えに失敗した場合は、既存版を復元する。

全スキルのインストール中に入れ替えが失敗した場合は、処理中のスキルを復元して処理を中止する。
失敗前にインストールしたスキルは、新しい配布物のまま残す。
失敗後に処理する予定だったスキルは変更しない。

利用者へ案内する正規のインストール手順は、このスクリプトの実行だけとする。
手動の `mkdir` や `cp` は、正規のインストール手順として記載しない。

## 変更手順

スキルの追加または変更では、次の順序を守る。

1. 利用例、適用条件、期待する結果を確定する。
2. 単独で目的を満たす方法と、既存の全スキルとの関係を確定する。
3. 実行時に必要なスクリプト、参照情報、素材を特定する。
4. 新規スキルでは、リポジトリの生成コマンドで雛形を作成する。
5. `SPEC.md` を新規作成または変更する。
6. `SPEC.md` を `SKILL.md` と実行時リソースへ反映する。
7. `skill-composition.json` の単独シナリオ、全 pair、必要な組み合わせシナリオと任意参照を更新する。
8. `agents/openai.yaml` とスキル別 `README.md` を実装内容へ合わせる。
9. 自動化できる振る舞いがある場合は、スキル固有のテストを追加または変更する。
10. ルート `README.md` の収録スキル一覧を更新する。
11. スキル固有のテストとリポジトリ検査を実行する。
12. 変更した単独シナリオと組み合わせシナリオを、現実的な依頼として前向き評価する。

仕様変更を伴わない誤字修正などでは、`SPEC.md` の変更を省略できる。

## 検証

変更したスキルは、完了前にリポジトリ検査を通す。
スキル固有のテストがある場合は、そのテストも pytest で実行する。

```bash
python3 -m pytest skills/{{skill-name}}/tests
python3 scripts/validate_skills.py {{skill-name}} [{{skill-name}} ...]
```

`tests/` がないスキルでは、対象スキルの pytest コマンドを省略する。
テストの有無にかかわらず、リポジトリ検査は省略しない。

リポジトリ全体へ影響する変更では、全スキルとツールの自動テストを検証する。

```bash
python3 scripts/validate_skills.py
python3 -m pytest tests skills
```

環境構築、複数スキルの指定、失敗時の扱いには、[`development-environment.md`](development-environment.md) の規約を適用する。
検査を通すために、実行時に必要な規則やリソースを削除してはならない。

リポジトリ検査では、対象スキルの指定有無にかかわらず `skill-composition.json` 全体を検証する。
自然言語で記載された規則の意味的な整合性は、台帳のシナリオを使った前向き評価で確認する。
前向き評価の結果は、変更時の最終報告へ記載し、台帳へ実行履歴として保存しない。
