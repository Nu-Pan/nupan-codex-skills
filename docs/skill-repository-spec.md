# スキルリポジトリの共通仕様

## 目的

この仕様は、モノレポ内の全スキルに共通する構造と保守方法を定義する。
新しいスキルも既存スキルと同じ方法で作成、変更、配布、検証できる状態を維持する。

このファイルは、スキルリポジトリの共通仕様の正本である。
共通規則を変更するときは、先にこのファイルを変更する。

各スキルの機能と実行時の振る舞いは、そのスキルの `SPEC.md` で定義する。
共通仕様とスキル固有仕様を重複させない。

## スキル名

スキル名は、ディレクトリ名と配布メタデータを結び付ける識別子として扱う。
スキル名は、次の条件をすべて満たす。

- 小文字の英字、数字、ハイフンだけを使う。
- 先頭と末尾にハイフンを置かない。
- ハイフンを連続させない。
- 64 文字以内にする。
- スキルの動作を短く表す名前にする。

同じスキル名を、次の場所で使用する。

- `skills/<skill-name>` のディレクトリ名
- `SKILL.md` の `name`
- `agents/openai.yaml` の `default_prompt` に含める `$<skill-name>`

## ディレクトリ構造

各スキルは、保守用ファイルと配布物を分離する。
標準構造を次に示す。

```text
skills/<skill-name>/
├── README.md
├── SPEC.md
├── AGENTS.md                     # スキル固有の保守規則がある場合だけ配置する
└── dist/
    ├── SKILL.md
    ├── agents/
    │   └── openai.yaml
    ├── scripts/                  # 実行時に必要な場合だけ配置する
    ├── references/               # 実行時に必要な場合だけ配置する
    └── assets/                   # 実行時に必要な場合だけ配置する
```

`skills/` の直下には、スキルのディレクトリだけを置く。
`dist/` の直下には、配布物を直接配置する。
スキル名と同じ配布用ディレクトリを `dist/` の下へ追加しない。

## ファイルの責務

### `SPEC.md`

`SPEC.md` は、スキル固有仕様の正本とする。
エージェントが配布物を再構築できるだけの情報を記載する。

仕様で定義する情報には、次の内容を含める。

- スキルの目的と成功条件
- 適用条件と対象外の範囲
- 入力、前提条件、優先順位
- 実行時の規則と手順
- 出力と検証条件
- 重要な規則の根拠、前提、重視する価値

見出し名と構成は、スキルの性質に合わせて変更できる。
リポジトリ共通の保守手順は記載しない。

### ルート `README.md`

ルート `README.md` は、リポジトリ全体の利用方法と保守方法の入口とする。
README 間で共通する利用情報と保守情報は、このファイルだけに記載する。

ルート `README.md` には、次の情報を記載する。

- リポジトリの概要
- 収録スキルへのリンクと概要
- `scripts/install_skill.py` による `.agents/skills/<skill-name>` への共通インストール方法
- スキルに共通する呼び出し方法
- リポジトリの開発方法と検証方法

### スキル別 `README.md`

スキル別 `README.md` は、利用者がスキルの機能と固有の使用方法を把握するための文書とする。
共通のインストール方法やリポジトリの保守方法は繰り返さない。

スキル別 `README.md` には、次の情報を記載する。

- スキルの概要
- `SPEC.md` と配布物へのリンク
- スキル固有の適用条件と使用方法
- 具体的な呼び出し例
- 暗黙の呼び出しなど、導入時に必要な固有設定

共通の利用方法が必要な場合は、ルート `README.md` へリンクする。
ルート `README.md` の収録スキル一覧にも、そのスキルへのリンクと概要を追加する。

### `AGENTS.md`

スキル固有の保守規則がある場合だけ、`AGENTS.md` を配置する。
ルート規則やこの共通仕様を繰り返さない。

### `SKILL.md`

`SKILL.md` は、スキルを使用するエージェントが実行時に従う情報だけを記載する。
YAML frontmatter には、`name` と `description` だけを記載する。

frontmatter は、次の条件を満たす。

- `name` をスキル名と一致させる。
- `description` に、スキルの機能と適用条件を記載する。
- `description` を 1,024 文字以内にする。
- 値を未確定のまま残さない。

本文は命令形で書く。
規則の根拠、リポジトリの保守手順、インストール方法は記載しない。
詳細な参照情報が大きい場合は `references/` へ分離し、`SKILL.md` から読み込み条件を明示する。

### `agents/openai.yaml`

`agents/openai.yaml` は、利用者向けの表示情報と呼び出し設定を定義する。
文字列値は引用符で囲む。

`interface` には、次の項目を必ず記載する。

- `display_name`
- 25 文字以上 64 文字以内の `short_description`
- `$<skill-name>` を含む `default_prompt`

アイコン、ブランド色、依存ツール、暗黙の呼び出し設定は、スキルに必要な場合だけ追加する。
`SKILL.md` を変更した場合は、表示情報と呼び出し設定が一致しているか確認する。

## 配布物

配布物には、スキルの実行時に必要なファイルだけを含める。
実行時リソースの用途を次に示す。

- `scripts/`: 繰り返し実行する処理または決定的な実行が必要な処理
- `references/`: 必要な場面で読み込む詳細な知識や仕様
- `assets/`: 出力へ組み込む雛形、画像、フォントなどの素材

必要なリソースディレクトリだけを作成する。
同じ情報を `SKILL.md` と `references/` に重複させない。

配布物には、次の保守用ファイルを含めない。

- `README.md`
- `SPEC.md`
- `AGENTS.md`
- `LICENSE`

## インストール

利用者は、リポジトリのルートで共通インストールスクリプトを実行する。
正規のインストールコマンドを次に示す。

```bash
python3 scripts/install_skill.py <skill-name> <target-repository>
```

`<target-repository>` には、既存のディレクトリを指定する。
相対パスと絶対パスのどちらも使用できる。
Git リポジトリであることは要求しない。

スクリプトは、配布物を `<target-repository>/.agents/skills/<skill-name>/` へインストールする。
`.agents/skills` がない場合は作成する。

同名スキルがすでに存在する場合は、配布物全体を置き換える。
旧版だけに存在するファイルや、導入先で加えられた変更は残さない。
置き換えでは、配布物を一時ディレクトリへコピーしてから既存版と入れ替える。
入れ替えに失敗した場合は、既存版を復元する。

利用者へ案内する正規のインストール手順は、このスクリプトの実行だけとする。
手動の `mkdir` や `cp` は、正規のインストール手順として記載しない。

## 変更手順

スキルの追加または変更では、次の順序を守る。

1. 利用例、適用条件、期待する結果を確定する。
2. 実行時に必要なスクリプト、参照情報、素材を特定する。
3. 新規スキルでは、リポジトリの生成コマンドで雛形を作成する。
4. `SPEC.md` を新規作成または変更する。
5. `SPEC.md` を `SKILL.md` と実行時リソースへ反映する。
6. `agents/openai.yaml` とスキル別 `README.md` を実装内容へ合わせる。
7. ルート `README.md` の収録スキル一覧を更新する。
8. リポジトリ検査を実行する。
9. 複雑なスキルでは、現実的な依頼を使って動作を検証する。

仕様変更を伴わない誤字修正などでは、`SPEC.md` の変更を省略できる。

## 検証

変更したスキルは、完了前にリポジトリ検査を通す。

```bash
python3 scripts/validate_skills.py <skill-name> [<skill-name> ...]
```

共通仕様またはリポジトリツールを変更した場合は、全スキルとツールの自動テストを検証する。

```bash
python3 scripts/validate_skills.py
python3 -m unittest discover -s tests -v
```

検査を通すために、実行時に必要な規則やリソースを削除してはならない。
